# Plan: Add PaymentMethod Enum for PaymentMethodId

## Context
`Order.PaymentMethodId` and `Payment.PaymentTypeId` are `byte?` fields with no enum backing — raw numeric IDs passed from the client and stored without type safety or validation. A proper `PaymentMethod` enum should replace the raw bytes.

## Changes

### 1. Create `PaymentMethod` enum
**File**: `Hydra.Ecommerce.Core/Enums/PaymentMethod.cs` (new)

```csharp
namespace Hydra.Ecommerce.Core.Enums;

public enum PaymentMethod : byte
{
    CreditCard = 0,
    PayPal = 1,
}
```

### 2. Update `Order` entity
**File**: `Hydra.Ecommerce.Core/Domain/Order.cs`

- Change `public byte? PaymentMethodId` → `public PaymentMethod? PaymentMethodId`
- Add `using Hydra.Ecommerce.Core.Enums;` (already present)

### 3. Update `Payment` entity
**File**: `Hydra.Ecommerce.Core/Domain/Payment.cs`

- Change `public byte? PaymentTypeId` → `public PaymentMethod? PaymentTypeId`
- Add `using Hydra.Ecommerce.Core.Enums;` (already present)

### 4. Update request/view models that use `byte?` for PaymentMethodId
**Files to update** (change `byte?` → `PaymentMethod?`):
- `Hydra.Order.Core/Models/ProcessPaymentRequest.cs`
- `Hydra.Order.Core/Models/CreateOrderRequest.cs`
- `Hydra.Order.Core/Models/OrderModel.cs`

### 5. EF Migration
Run `dotnet ef migrations add AddPaymentMethodEnum --project Hydra.Infrastructure --startup-project Hydra.Web` to persist the column type change in PostgreSQL.

## Verification
- `dotnet build Hydra.slnx` compiles without errors
- Migration generates without issues
