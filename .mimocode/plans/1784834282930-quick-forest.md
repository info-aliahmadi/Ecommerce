# Order & Shipment Architecture — Explanation

No implementation needed. This was a read-only research task.

The user asked for an explanation of how orders and shipments work together. The full explanation has been provided in the conversation above.

Key findings:
- Order is the central aggregate with 3 independent status tracks (order, payment, shipping)
- ShipmentItem bridges Shipment and OrderItem with a Quantity field, enabling split shipments
- Shipping status lives on the Order, not the Shipment entity
- Shipment entity tracks timeline via date milestones (ReadyForPickup, Shipped, Delivery)
- Payment is a separate track with its own lifecycle
- `Order.ShipmentId` is a vestigial column with no EF relationship configured
