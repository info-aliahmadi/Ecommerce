# Plan: Add structured contact info to Shipment entity

## Context
The `Shipment` entity has only a `ShippingAddressSnapshot` string. It's never auto-populated and has no structured access to recipient name, phone, or email. The user wants structured fields for carrier integration and notifications. All needed data already exists in the codebase.

## Data sources (all already available via Order navigation)
- **Name** → `Order.User.Name` (from `Hydra.Auth.Domain.User`)
- **Phone** → `Order.Address.PhoneNumber` (from `Address` entity)
- **Email** → `Order.User.Email` (from `IdentityUser` base class)

## Changes

### 1. Add properties to `Shipment` entity
**File:** `Hydra.Ecommerce.Core\Domain\Shipment.cs`

```csharp
public string RecipientName { get; set; }
public string PhoneNumber { get; set; }
public string Email { get; set; }
```

### 2. Update EF configuration
**File:** `Hydra.Ecommerce.Core\EntityConfiguration\ShipmentConfiguration.cs`

Add max-length config for the new fields (e.g., `RecipientName` → 200, `PhoneNumber` → 50, `Email` → 200).

### 3. Update `ShipmentModel` DTO
**File:** `Hydra.Order.Core\Models\ShipmentModel.cs`

Add matching properties: `RecipientName`, `PhoneNumber`, `Email`.

### 4. Auto-populate from Order on creation
**File:** `Hydra.Order.Api\Service\ShipmentService.cs`

In the `Add` method, after mapping the model to the entity, load the related `Order` (with `User` and `Address` includes) and auto-populate:
- `RecipientName` from `Order.User.Name` (if caller didn't provide)
- `PhoneNumber` from `Order.Address.PhoneNumber` (if caller didn't provide)
- `Email` from `Order.User.Email` (if caller didn't provide)

This ensures shipments always have contact info even if the API client doesn't send it, while still allowing override.

### 5. Update service mapping
**File:** `Hydra.Order.Api\Service\ShipmentService.cs`

Ensure both `Add` and `Update` methods map the new fields between `ShipmentModel` ↔ `Shipment`.

### 6. EF migration
```bash
dotnet ef migrations add AddShipmentContactInfo --project Hydra.Infrastructure --startup-project Hydra.Web
```

## Verification
1. `dotnet build Hydra.slnx` passes
2. Migration applies cleanly
3. New fields appear in Swagger schema for shipment endpoints
